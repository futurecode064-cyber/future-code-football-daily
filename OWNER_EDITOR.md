# Owner daily content editor

Entry point: `https://future-code-football-daily.pages.dev/editor/`.

The existing owner session gates the complete editor and all `/api/editor/*` endpoints. Public brands retain their current routes. Server-held `FCD_EDITOR_GITHUB_TOKEN` is the only new production secret. Setup is documented in the owner-only `/editor/setup.html`; it needs fine-grained Contents read/write and Actions read/write on the source and delivery repositories. The token is never sent to the browser, stored in localStorage or committed. Existing ChatGPT connector authorization does not provision this secret.

Editor flow: load canonical data at one commit → enter Burmese previews, fixtures, morning/latest odds, Special Choice, records and yesterday's verified results → local draft/backup → server validation → owner confirmation → atomic source commit with expected-head conflict check → dispatch existing guarded production workflow → poll delivery and live publication marker. A successful source save is never labelled a successful live deployment. Dispatch failures retain the commit and offer a delivery-only retry. Requests are same-origin JSON with an explicit custom header and authenticated session. Request bytes are capped at 1.5 MB.

Only data files are publishable through the API, with server-selected paths. Old archives are preserved; yesterday's result updates merge only status/score/source/date fields onto authoritative original fixtures. No destructive force push. The existing production marker drift guard and Python daily guard remain enabled. Server schema validation cannot verify football facts; owner confirms evidence. No automatic sports research, AI-written articles, or PDF OCR is claimed. League logos and downloadable client graphics continue to use the shared existing renderers. Static pre-rendered evening PNGs are not regenerated by the editor; use the existing separate PNG workflow if needed.

The editor can load and back up a draft before credentials are connected, subject to GitHub public API rate limits. Publishing is only enabled server-side after credential setup. Preview deployments must not inherit production writing credentials. Local drafts contain unpublished editorial content on the owner's device; use a trusted device. Token expiration/revocation is surfaced as an actionable GitHub error. The Free Worker CPU limit still applies; practical payload sizes should be measured under production traffic.

Acceptance: existing Node regression suite plus editor API tests. Real GitHub write/dispatch/live verification requires configured production credential and an actual owner-approved daily payload; mocked integration tests do not prove production delivery.
